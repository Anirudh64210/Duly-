## Findings

1. **blocking (SPEC-W2 point 16; point 17 "nothing lost"). A missing documents.bin makes the
   next launch delete every stored document.** docstore.ts:229-232 and 618-626.
   - Input: two documents added, then documents.bin moved out of the data folder (a sync tool,
     a restore of only part of the folder, a user tidying up), with keys.bin kept, then a
     relaunch.
   - What happens: `load()` takes the missing index as an empty one with a good D. The launch
     sweep then deletes every file in files/, because no row names them. P3 printed "files
     before: 2", then "after relaunch: 0". With documents.bin put back, opening either document
     gives file_damaged.
   - The code already refuses the opposite case (an index with no keys.bin) as "can never be
     read again: refuse, change nothing" at line 230. A missing index with files present needs
     the same: refuse, or at least do not sweep. A first add that crashed before its first
     index write leaves at most one orphan.
   - No test covers this.
2. **should_fix (point 17). A fork in replaces drops a version from versions().**
   docstore.ts:327-331, 436-460 and 521-526.
   - Input: `add([a.pdf, b.pdf], old)` from one dialog pick with several files. Or
     `update(c, {replaces: old})` when b already replaces old.
   - What happens: P2 gave versions(old) = [b.pdf, i20.pdf], and a.pdf, which replaces old, is
     missing. P2b gave versions(b) = [b.pdf, old.pdf], and c is missing.
   - Either refuse a second replacer as bad_replaces, or list both.
3. **should_fix (point 22). One reminder becomes two Notifications across a relaunch.**
   reminders.ts:22 and 27-36.
   - Input: a reminder on 2026-10-06 with time_of_day 09:00, shown at 09:00. Duly quits and opens
     again at 09:40 the same day.
   - What happens: the `shown` set lives only in memory, so the new process shows it again. P5
     printed 2.
4. **should_fix (point 13, kind spec_gap). add changes the store and then gives no answer.**
   docbridge.ts:178-195 and 306-307.
   - Input: `documents.add {from: "dialog"}` with 51 files picked. The dialog allows
     multiSelections with no cap, and `add_reply.added` has maxItems 50.
   - What happens: P1 got "not a documents bridge reply: /: anyOf" on the page, yet the index
     holds 51 rows and files/ holds 51 files.
   - Cap the picked list, or answer within the contract.
5. **should_fix (point 13). With history over 20000 lines, list is never answered again.**
   docstore.ts:402, 532, 541 and 587.
   - Input: an index whose history holds 20001 lines. Every add, update, remove, restore and
     export adds one, and nothing trims them.
   - What happens: P7 got "not a documents bridge reply" on every documents.list, while updates
     are still accepted. Documents is dead from then on. The same holds at 5001 documents and at
     a chain of 201 versions (versions maxItems 200).
6. **should_fix (point 15, kind missing_test). The tests pass with one nonce for every chunk.**
   - Input: mutant M3, `nonce.writeUInt32BE(0, PREFIX)`.
   - What happens: all 66 tests pass, as they do for M1 (last flag dropped) and M2 (chunk index
     out of the additional data).
   - The whole-file SHA-256 check in read() catches every chunk fault on its own, so the
     per-chunk binding of point 15 is untested. Reusing the nonce under one F breaks GCM. The
     tests check outcomes, and this one changes the ciphertext, not the outcome.
   - Turning off the SHA-256 check as well (M21, M22) is caught, so the two layers do cover for
     each other.
   - A test that decrypts chunk 1 with the counter at 1, or checks that the nonces differ, would
     catch it.
7. **should_fix (point 15, kind missing_test). The read-back comparison of an add is untested.**
   docstore.ts:317-318.
   - Input: mutant M6, which removes the check that decrypts back and compares the SHA-256.
   - What happens: all tests pass, because the crash test throws from step() and never reaches
     the comparison.
   - M13 also survives: with the reply check in docbridge.ts:306-307 removed, no test fails,
     because no test makes a reply outside the contract (finding 4 is one that would).
   - M17 also survives: the test that the size is refused "before reading it" passes with the
     stat check removed.
8. **should_fix (reviews/w2-p3.md finding 2, kind regression). A published file that is not
   UTF-8 still raises.** api/case.py:89-92.
   - Input: pipeline/published/bad.json holding bytes ff fe 7b.
   - What happens: `read_text()` raises UnicodeDecodeError, which is not JSONDecodeError, so
     published_updates raises and GET /v1/updates gives a 500 again.
   - Catch `(UnicodeDecodeError, json.JSONDecodeError)`, or ValueError, which covers both.
9. **note (kind other). Export can write plaintext into Duly's own data folder.**
   docbridge.ts:212-259.
   - Input: the folder dialog pointed at the data folder.
   - What happens: P6 exported 1 and left a.pdf in plaintext beside documents.bin.
     "Delete everything" does not remove it.
   - A pick inside the data folder could be refused as add refuses one.
10. **note (kind other). An empty image cannot be opened.** docbridge.ts:208.
    - Input: an empty .png. The contract's data_url pattern needs at least one base64 character.
    - What happens: the reply fails its own check and the call is rejected, not refused.
11. **note (kind overbuilt).** docbridge.ts:79-100. openFree and freeName each build the same
    "stem (n).ext" names. One generator of candidate names could serve both.
12. **note.** src/buildpython.test.ts fails on a clean checkout because pipeline/published/ is

## What holds

- Frame checks are on all four channels, through the one mayUseCase rule (main.ts askedFrom).
- Every call is checked against its contract before anything is read or forwarded, and so is
  every reply.
- The preload sends only webUtils paths for drops. Main also refuses a path that is not
  absolute, a folder, a file inside the data folder by any path, a file over 50 MiB and a
  duplicate.
- D is written only wrapped. F appears only inside the encrypted index (tested with keyForms).
- Chunk faults are caught by GCM and again by the SHA-256.
- A crash in any step of an add leaves no row, and the sweep at launch removes .part files and
  orphans.
- A bad index or a bad state.bin is refused and kept.
- Reminders show exactly the title and body saved in state. Main writes no words of its own,
  and every refusal is a code.
- Engine replies never carry the engine's own text, the socket or the token.

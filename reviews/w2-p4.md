## Findings

1. **blocking (SPEC-W2 point 16 as D96 amends it, and point 13; kind regression). A first add
   that stores nothing locks Documents as index_missing after the next launch.**
   docstore.ts:255-262, 433-440 and 249-252.
   - Input: a new student whose first add is one empty file. A folder or a 60 MiB scan does the
     same. Then Duly quits and opens again.
   - What happens: add answers ok with the file skipped (empty, not_a_file or too_large). But
     load(true) has already written keys.bin, and no documents.bin is ever written, because only
     a stored file saves the index. At the next launch, keys.bin without documents.bin is
     index_missing.
   - From then on list and add are refused for good (N1: all three inputs printed
     `{"ok":false,"refused":"index_missing"}` for list and for a new add). The page has to send
     the student to "Delete everything" to add a first document.
   - The same happens when the first index write fails (N2: disk.write of documents.bin throws
     once, so the add skips cannot_store, and every call after a relaunch is index_missing).
   - D96 says index_missing is for "a missing index", and the contract says "so the documents
     cannot be named". Here no index was lost and no document exists, and the store itself made
     that state on an input D96 names ("an empty file is skipped").
   - No test covers it. review_w2p4_1 covers a full store and an empty folder, not keys.bin on
     its own.
   - A fix that stays inside D96: write the empty index in the same load(true) step that first
     writes keys.bin. Or create D and keys.bin only once a file is about to be stored, and save
     the index in that add. Then test the three skips and a failed first save, each followed by
     a relaunch.
2. **should_fix (SPEC-W2 point 18; kind other). reminders-shown.json gives away the reminder
   dates that state.bin encrypts, and Delete everything leaves it.** reminders.ts:24-26 and
   50-63.
   - Input: a reminder loop.b on 2026-10-07, shown. Then the file `<userData>/reminders-shown.json`
     is read, from a copy of the data folder (the threat-model row for "a copy of the data folder,
     but not the Mac login").
   - What happens: the file holds unsalted sha256("<id> <date>") in plain text. My probe S2 tried
     3 ids over 4 years of dates and printed `recovered: [ 'loop.b 2026-10-07' ]` in about a
     millisecond. Reminder ids are product keys and easy to list.
   - After state.clear (plan set to null) the file is still there (N5: true). It is not among
     the files "Delete everything" removes.
   - Point 18 keeps reminder settings in state.bin under safeStorage. Encrypt the file with
     safeStorage as state.bin is, or key the hash with a secret kept that way. Remove it with
     state.clear.
3. **should_fix (contract store_full description; kind spec_gap). store_full is refused before
   the store holds 5000.** docstore.ts:353.
   - Input: 4999 documents held, then add([new.pdf, a duplicate of a held one]).
   - What happens: S1 printed `{"ok":false,"refused":"store_full"}`, though only one document
     would be added and the store would then hold exactly 5000. The same add with just new.pdf is
     accepted.
   - The contract says store_full means "the store already holds 5000 documents".
   - Either count the files that would really be stored, or reword the contract.
4. **should_fix (point 16, point 17 as D96 amends them; kind missing_test). Three parts of the
   fix are untested.**
   - N1b: index_missing only when keys.bin is present (files/ alone not checked). All tests pass.
   - N1c: index_missing only when files/ holds a file (keys.bin alone not checked). All tests pass.
     D96 names "keys.bin or a file" as two cases, and each needs a test.
   - N4c: in badReplaces, count the versions above id as 1 (docstore.ts:501). All tests pass, so
     the 200 cap through update on a document that already has newer versions is untested.
5. **note (kind overbuilt).** The multi-file replaces rule is in two places, docbridge.ts:207 and
   docstore.ts:348. Only the bridge's counts skipped drops, which is what the contract says
   ("the add holds more than one file"). The store's copy guards direct callers. One of them, with
   one test, would do. Also, the unreachable `throw new Error("no free name")` after each infinite
   namesFor loop (docbridge.ts:101 and 111) is there only for the type checker.
6. **note (kind other).** api/case.py:92-95. If a folder named `x.json` is in
   pipeline/published, published_updates raises IsADirectoryError and GET /v1/updates gives 500.
   The founder controls that folder, so this is a note. Catching OSError beside ValueError would
   close it.
7. **note.** build-python.sh:121 uses a here-string. That fails in a sandbox where bash 3.2
   cannot write its temp file (the three buildpython failures above). Process substitution, as
   line 111 already uses, would not need a temp file. This is not a fault in the jail.
8. **note.** An index already over 20000 history lines, which only the pre-fix build could

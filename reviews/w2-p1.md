## Findings

### 1. Blocking: `exists` and `none` still go unknown for the whole selection, so a gap in one job removes another job's concluding evaluation window
`engine/path.py:475` (`_cond`, exists and none) and `:479` (count_below, count_at_most) read
`_select`, which is still None when any one record is undecided, even when a decided record
already settles the condition. stem_job_end.evaluation_final asks `exists` another job under the
same card that has not ended by this job's end.

Input D4 (TMPDIR/rvw2g/p1.py, and p5.py through `POST /v1/compute`): STEM card a2; w1 under a2
2026-07-01 to 2026-08-02; w2 under a2 from 2026-08-03 with no end. w1's concluding evaluation
window is 2026-08-02 to 2026-08-12 (2026-08-02 plus 10, stem.evaluation_due_days, 8 CFR
214.2(f)(10)(ii)(C)(9)(i), "no later than 10 days following the conclusion of ... his or her
practical training opportunity"). Add w3 under a2 from 2026-09-01 with end `not_sure`: w2 alone
already makes `exists` true, yet w1's window becomes null, w1's stage state turns unknown, and
nothing names w1 or says why (the only trace is the judgement `w3.end.not_sure`). The mission
says a gap in one record never removes another record's known deadline. The fix is the one the
re-review asked for, carried to the conditions: exists is true if any decided record matches,
none is false if any decided record matches, and only then unknown when some are undecided.

### 2. Blocking: a counter's scope with one undecided record drops every other record's count and limit day
`engine/path.py:1100` (`_counter`): `found = self._select(scope["of"], ...)`; `if found is None:
return result`. unemployment.opt_card groups by record, so each card's count reads only that
card and its own jobs.

Input C (TMPDIR/rvw2g/p2.py): masters p1 ending 2026-05-15, post-completion OPT a1 2026-06-01 to
2027-05-31, no job. a1 gives `unemployment.opt_card.a1` 121 and `.limit_day` 2026-08-29 (June 30
days, July 31 to 61, August 29 to 90; the limit is opt.unemployment_limit_days, 90). Add a3, an
authorization for p1 with card 2026-06-01 to 2026-12-31 and no type: both a1 items vanish, and
so does the judgement `unemployment.opt_card.at_or_over_limit.a1`. a3 is asked about, but
nothing says a1's count and limit day are withheld because of a3. The limit day is SPEC-W2 46
N2, this plan's own date. Same at 41990c1; the counter code predates W2-P1, but the plan's goal
is the class. Use `_split` here too and withhold only the groups an undecided record could join.

### 3. Blocking (regression from fix 2): an unreadable end is read as "no end", and another job's date is shown on that guess
`engine/path.py:187` (`_field` now gives ABSENT for a date that does not parse) with

## Findings

1. **One file in pipeline/published/ that is not JSON makes GET /v1/updates a 500 on both
   apps** (api/case.py:87, review finding 2, still open). No valid update is served either.
   Only the founder's approval writes that folder, so no user can cause it, but the route then
   shows nothing at all.
2. **The route's 422 for a missing holiday row cannot run** (api/local_routes.py:34 and
   :130 to 131, review finding 1). Its words say the opposite of openapi's "a request the
   engine cannot date is not a 422". Mutant M17 survives because the code is dead.
3. **The drafts carry no `article` paragraphs.** K5 added them for the Updates screen
   (point 30); the drafts hold headline, plain and claims only. They are drafts, so this waits
   on the screen's plan and the founder.
4. **The scheduler is half built.** engine.schedule dates timers, but nothing plans them: no
   Loop module in web/src, no Notification in main, no .ics, no digest, no weekly budget.
5. **Nothing is published.** pipeline/published/ does not exist, so /v1/updates is empty on
   both apps, and every law update shown to a person still waits on the founder's approval.
6. **A planning base capped to a rule item stays planning** (review note). It follows the
   contract as written; the founder may want the cap to decide.
